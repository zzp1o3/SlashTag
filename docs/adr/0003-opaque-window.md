# 0003 - 使用不透明窗口 + WindowChrome，放弃 9px 硬阴影

- 状态：已接受
- 日期：2026-11-03

## 背景

像素风便签的最初实现按设计稿使用 `AllowsTransparency="True"` 的分层窗口，以便在窗口外绘制 9px 的黑色硬阴影。实现完成后发现，任务编辑对话框里的 TextBox 在 125% 缩放下字形被横向压缩、彼此重叠，文字无法正常阅读和输入。

## 诊断

- 用一个窗口内并排的默认 TextBox 与像素样式 TextBox 做对照：默认文本框正常，像素文本框异常。
- 直接原因是自定义 TextBox 模板把 `Padding` 又作为 `ScrollViewer` 的 `Margin` 应用了一次，破坏了 TextBox 内部的文本尺寸计算；把模板收敛为与默认模板一致的结构后，文字恢复正常。
- 分层窗口本身在非整数 DPI 下也存在额外的文本/控件渲染风险，并且与 `WindowChrome` 不兼容；保留它意味着继续自绘缩放。

## 决策

- 主窗口与对话框改为**不透明窗口**。
- 主窗口使用 `WindowChrome`，获得原生边缘缩放与系统窗口阴影。
- TextBox 模板只保留配色与焦点边框，内部结构与默认模板一致。
- 放弃设计稿里的 9px 硬阴影；像素边框、黄色标题条、网格底纹等其余视觉保持不变。

## 备选方案

- **保留分层窗口，只修 TextBox 模板**：可以恢复硬阴影，但仍然处在「分层窗口 + 分数 DPI」的风险区，且无法使用 WindowChrome，需要继续维护自绘缩放与拖拽。
- **降低 DPI 感知**：文字会被系统位图放大而变模糊，不采用。

## 后果

- 窗口阴影改由系统提供，不再是像素风的硬投影。
- 125% 缩放下的文字输入、缩放、拖动均验证正常。
- 后续如果一定要恢复硬阴影，需要重新引入 `AllowsTransparency` 并自绘缩放，同时重新验证文本渲染。
